## 1. 本線は何か

- **公式の先行き** = 計画どおりに定植した場合の累計在庫（緑）。
- **いまの畑だけ**（定植済・灰）が先でゼロに見えるのは、定植催促。公式予測ではない。
- 確定出荷は **GCALのみ**。manual は使わない。

## 2. 定植済と計画は、いつ一致するか（必須）

**いま植えても収穫が届かない期間は、定植済累計 ＝ 計画累計。**

- 起点・残出荷・週の切り方を同じにする。系列を別にゼロ起算しない。
- 計画累計 = 予測の累計余剰（既存株・残出荷）を土台に、まだ植えていない将来収穫だけ足す。
- 定植済累計も **同じ土台**。差が出てよいのは、次定植の収穫が実際に載る週から。
- 2026-08時点の目安は **9/20週まで差なし**（栽培日数の結果。日付を固定仕様にしない）。

やってはいけない例:

- 需給②の定植済累計だけ当週ゼロ起算にして、計画より下に見せる。
- 栽培中ベッドの「次定植」収穫を、今サイクルより前の週に載せる。

## 3. 回転と定植遅れ

- 収穫後 **5日前後** に次定植する計画を、画面ボタンなしで自動維持する（`GF_REPLANT_GRACE_DAYS = 5`）。能力・累計の計画線はこの前提。
- **定植遅れ**に出してよいのは、空いていて予定日を過ぎたベッドだけ。
- **栽培中のベッドは定植遅れに出さない。** 植えられない。出すのは破棄リスクのみ。

## 4. 営業（余りと減）

- 当週〜直後の定植済プラスは、先の出荷の持ち越し。スポットで売らない。
- 先々の余りは **計画ライン** で拡大提案する（実行が追いついているとき）。
- 低温期の能力減は、在庫割れを待たず早めに営業へ。開始週が10〜2月のときだけ「低温」と書く。8月を低温としない。
- 営業アラートのラベルは **一時** / **トレンド** / **遅れ** のみ。
- トレンドは連続した週を1行にする（開始週〜終了週、kg/週）。一時は週ごと。
- 減少トレンドが累計余剰で賄えるときは、その旨と「ベッドあたり収穫量が ●●kg を下回ると累計がマイナスになる」を付ける。賄えないときはその旨を書く。
- 拡大より減少の伝達を優先する。

## 5. 需給シミュレーション③

意図（実装が違っていても、仕様はこちら）:

| ボタン | 意味 |
| --- | --- |
| ① 一時を直載せ | アラートのうち **一時** を、該当週のGCALにそのまま足し引きする。トレンドは載せない |
| ② 平準化（弱） | **一時ではない** 数か月トレンドを均す。③と同じ計算で、週あたり幅は半分 |
| ③ 平準化（強） | ②と同じ均しを満額で載せる |

直載せにトレンドだけ載せて一時を除外するのは、仕様違反。

## 6. 予測kg

- 当週・翌週: 栽培中再予測のkg。
- 2週先以降: 日数は再予測、kgは定植時モデル。部分収穫の⑤は上書きしない。
- 完了サイクルへの後付け予測でMAPEを作らない。

## 7. 用語・表示

- 週ラベルは日曜始まり **「8/9週」**（年なし）。日付は `Y-m-d`。
- 画面のkgは整数。
- 定植済予測 / 未収穫ベッド / 残出荷 / 累計余剰。旧称「オープン予測」をUIに出さない。
