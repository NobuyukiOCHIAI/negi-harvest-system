## 1. 本線は何か

- **公式の先行き** = 計画どおりに定植した場合の累計在庫（緑）＝ **実績（いまの畑）＋計画（次定植）**。
- **いまの畑だけ**（定植済・灰）が先でゼロに見えるのは、定植催促。公式予測ではない。
- **下チャートの青点線（累計余剰・定植済ベース）は営業判断の現実線**。緑に寄せていく手段は定植計画。青は「今売れる／足りない」の判断に使う。
- 確定出荷は **GCALのみ**。manual は使わない。

## 2. 定植済と計画は、いつ一致するか（必須）

**いま植えても収穫が届かない期間は、定植済累計 ＝ 計画累計。**

- 起点・残出荷・週の切り方を同じにする。系列を別にゼロ起算しない。
- 計画累計 = 予測の累計余剰（既存株・残出荷）を土台に、まだ植えていない将来収穫だけ足す。
- 定植済累計も **同じ土台**。差が出てよいのは、次定植の収穫が実際に載る週から。
- 2026-08時点の目安は **9/20週まで差なし**（栽培日数の結果。日付を固定仕様にしない）。

やってはいけない例:

- 需給②の定植済累計だけ当週ゼロ起算にして、計画より下に見せる。
- 栽培中のベッドの「次定植」収穫を、今サイクルより前の週に載せる。

## 3. 回転と定植遅れ

- 収穫後 **5日前後** に次定植する計画を、画面ボタンなしで自動維持する（`GF_REPLANT_GRACE_DAYS = 5`）。能力・累計の計画線はこの前提。
- **定植遅れ**に出してよいのは、空いていて予定日を過ぎたベッドだけ。
- **栽培中のベッドは定植遅れに出さない。** 植えられない。出すのは破棄リスクのみ。

## 4. 営業（余りと減）

- 営業が重視するのは **青点線（定植済累計余剰）の直近**。緑は定植計画の到達点。
- 当週〜直後の定植済プラスは、先の出荷の持ち越し。スポットで売らない。
- 先々の余りは **計画ライン（緑）** で拡大提案する（実行が追いついているとき）。
- **秋〜冬など同世代が弱い局面で、青点線だけが楽観のまま残るのは営業リスク**（§6の同世代補正の動機）。
- 低温期の能力減は、在庫割れを待たず早めに営業へ。開始週が10〜2月のときだけ「低温」と書く。8月を低温としない。
- 営業アラートのラベルは **一時** / **トレンド** / **遅れ** のみ。
- トレンドは連続した週を1行にする（開始週〜終了週、kg/週）。一時は週ごと。
- 減少トレンドが累計余剰で賄えるときは、その旨と「ベッドあたり収穫量が ●●kg を下回ると累計がマイナスになる」を付ける。賄えないときはその旨を書く。
- 拡大より減少の伝達を優先する。

## 5. 需給シミュレーション③

意図（実装が違っていても、仕様はこちら）:

| ボタン | 意味 |
| --- | --- |
| ① 一時を直載せ | アラートのうち **一時** を、該当週のGCALにそのまま足し引きする。トレンドは載せない |
| ② 平準化（弱） | **一時ではない** 数か月トレンドを均す。③と同じ計算で、週あたり幅は半分 |
| ③ 平準化（強） | ②と同じ均しを満額で載せる |

直載せにトレンドだけ載せて一時を除外するのは、仕様違反。

## 6. 予測kg・日数の起点

- 予測の日数・収量の起点は **定植日**（`plant_date`）。収穫予定 = 定植 + pred_days。
- **播種日（`sow_date`）は入力・履歴として残す。現状の予測モデル特徴量には使わない**（育苗待ち日数を特徴に載せない。固定値プレースホルダのみ可）。
- 当週・翌週: 栽培中再予測のkg。
- 2週先以降: 日数は再予測、kgは定植時モデル。部分収穫の⑤は上書きしない。
- 完了サイクルへの後付け予測でMAPEを作らない。**完了サイクルの実績kgは変更しない。**

### 6.1 同世代補正（未収穫のみ・営業リスク低減）

目的: 同時期定植の実績が定植時予測を下回り続けるとき、**未収穫の同世代**の予定kgが楽観のまま青点線に残るのを防ぐ（特に秋〜冬）。

- **対象**: 未収穫サイクルのみ。完了床の実績は触らない。
- **単発では動かさない**: 同世代で複数床の実績が揃ってから。1床だけでは補正しない。
- **部分収穫（⑤・途中）**: 同世代補正の**証拠にも発火にも使わない**（他ベッドへ伝播しない）。そのベッド単体の最終予測への反映は従来どおり可。上振れの引き上げは必須ではない。
- **部分の最後（全部・完了）**: 面積が全体になりサイクルが閉じた時点で、その床は**完了実績**として証拠に数える。乖離条件を満たせば同世代の未収穫へ発火してよい（完了床の実績kg自体は書き換えない）。
- **緑への反映**: 緑＝実績＋計画。同世代補正は未収穫の実績側（定植済）に載せる。再予測するなら計画側も同じ前提で変わる（青だけ下げて緑を据え置かない）。
- **記録**: 補正した場合は理由（同世代・床数・乖離）をログ／payloadに残す。画面バッジは必須にしない（「明示」＝黙って上書きしないための記録）。

発火閾値（v1）:

| 項目 | 値 |
| --- | --- |
| 同世代窓 | 定植日 **±5日** |
| 優先範囲 | 同一 `group_type` 優先。ピア不足時のみ全体 |
| 証拠床 | **完了床のみ**（途中の部分⑤は数えない。全部で閉じた床のみ） |
| 最低証拠数 | 同世代で乖離条件を満たす完了床 **≥2** |
| 乖離条件 | 実績合計kg／定植時予測kg **< 0.90** |
| 補正先 | 未収穫の同世代のみ。完了実績は触らない。上振れ伝播なし |
| 補正の強さ | 証拠床の中央値比率へ寄せる。フロア **max(0.75, median_ratio)** |
| 季節ゲート | なし（通年同一ルール） |

## 7. 実収穫量・生育日の年次モニター

- **実収穫量** `actual.php`: 収穫月ごとの kg・ベッド数の年次比較（既存）。
- **生育日** `growth_days.php`: **定植→収穫開始** 日数の年次比較。画面上部で月の归属を切替:
  - **収穫日ベース** … 収穫開始月で集計（実績トレンド監視）
  - **定植日ベース** … 定植月で集計（Excel時代の「同時期定植の見え方」可視化）
- 主指標は定植→収穫開始。定植→収穫完了は参考。播種起点の日数は主モニターにしない。
- 定植日ベースは **可視化のみ**。予測への反映は特徴量（前年同時期日数・類似ベッド平均日数）側。モニター切替は手作業予測の代替ではない。
- 月別の **ばらつきSD** は、月内の生育日数の散らばり。目安は回転1スロットの **5日前後**、**10日未満**なら平常幅、**10日以上**は切り分け優先。同月の平均・前年比とセット。画面注釈に記載。

## 8. 気温データ（UltraNet / weather_daily）

- 予測特徴量の気温は **`weather_daily` の実測**（将来予報は使わない）。
- 取得元: **UltraNet（UTNET）** `https://sedia-utnet.com` / ハウス「水耕ハウス」(id=6229)。
  - 日次CSV（センサデータ・過去3ヶ月・平均24時間）の **温度1〜4地点平均** を `temp_avg`、各地点最大の最大を `temp_max`、各地点最小の最小を `temp_min` とする。
  - JOB: `jobs/sync_ultranet_weather.php` → 続けて鮮度チェック。認証は `db.local.php` の `ultranet_user` / `ultranet_pass`（秘密は正本に書かない）。
- **取得失敗・更新停止は即時アラート**する。黙って止まったままにしない。
  - 判定: 当日バッチ時点で `MAX(date) < 昨日`、または取得JOB自体の失敗。
  - 記録: `alerts(type=data_missing, kind=weather_stale|weather_fetch_fail)` ＋運用ログ。設定があればメール通知（宛先: `db.local.php` の `alert_to`）。
  - 予測・気温比較画面にも滞留バナーを出す。
- **優先順位**: UltraNet から取れる期間は **実測取込を優先**。類推埋めしない。
- **類推埋めは、UltraNet から取れない過去欠損だけ**（予測を止めない応急）。条件:
  - UltraNet上も0／欠測の日を含む。取れる実測がある日は類推しない。
  - 前後の実測がある短い欠損は直線補間を優先。
  - 埋めた行は **`is_imputed=1` 必須**。実測が来たら上書き置換。
  - 補完してもアラートは出す（補完は黙殺の代替ではない）。
  - 気温比較の「実測トレンド」表示では補完を明示する。
## 9. 用語・表示

- 週ラベルは日曜始まり **「8/9週」**（年なし）。日付は `Y-m-d`。
- 画面のkgは整数。日数は整数。
- 定植済予測 / 未収穫ベッド / 残出荷 / 累計余剰。旧称「オープン予測」をUIに出さない。
- 面積比の表示は UI分数（`1/4`〜`3/4`・`全体`）のみ。`%` や `—` は出さない。
  完了サイクルの旧小数は kg 比重で分数へ**DB書き換え**し、合計がちょうど全体になるように揃える（予測には使わない。集計ずれ防止）。
